# 分层规范与恢复协议

当用户询问项目规范、例外、上下文压缩或“继续”时读取本参考。它只定义规则的归属和优先级；完整恢复步骤统一见 [workflow.md](workflow.md)。

## 三个范围

### Skill 全局底线

全局底线写在 `SKILL.md`，包括：从工件恢复事实、不自行批准阶段、重大范围变化回到最早受影响工件、不覆盖用户资料、不伪造未运行的证据，以及小改动按风险走短路径。这些底线不能被项目文件静默放宽；要改变行为就修改 Skill。

### 项目常驻规范

目标项目确认后，`.agent/rules/always.md` 记录跨工作项长期有效的事实和约束，例如技术栈、真实路径、检查命令、接口/安全/部署要求和生成目录边界。

初始化器只创建 `.agent/rules/`，不会猜测或填写规则。首次初始化后，Agent 先检查仓库并提出草案；用户确认后才写入 `always.md`，并设置 `status: active`、`configured: true`。规则未确认时可以讨论、设计和做不依赖未知规则的只读检查，但不能实现、部署、迁移或变更数据。

### 工作项约束

`.agent/changes/<WORK编号>-<中文名称>/requirements.md` 保存本次目标、范围、验收和特殊约束。下游 proposal、design、tasks 只能在已批准范围内收敛。一次变更的取舍放在工作项；跨变更决策放 `.agent/notes/`；稳定共享协议放 `.agent/specs/` 或 `.agent/references/`；长期可检索知识放 `.agent/memory.md`。

## 优先级与冲突

项目文件按以下顺序处理：

```text
AGENTS.override.md
  > AGENTS.md
  > .agent/rules/always.md
  > 当前工作项 requirements.md
  > proposal.md / design.md / tasks.md
```

更具体的文件不能突破平台安全、用户授权或更高层约束。只有冲突可能影响目标、验收、公共行为、接口、数据、安全、部署或架构时才停止；已批准范围内的局部事实修正可记录理由后继续，不确定且有实质影响时只问一次。

## 上下文压缩与“继续”

换会话、上下文压缩或用户只说“继续”时，按 `workflow.md` 重新读取入口规则、项目常驻规范、状态、工作项需求和当前阶段工件；聊天记录、时间戳和记忆不能代替这些事实。
